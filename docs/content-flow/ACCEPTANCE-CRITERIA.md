# Acceptance criteria

These are proposed executable scenarios for the agreed full MVP. No claims of completed testing. Use fixtures, temporary workspaces and fake providers; no live publication or paid calls in tests.

## Functional scenarios

1. INIT: given detailed existing profile, ask only gaps; optional avatar absent does not block. Pause/resume preserves answers; approval activates settings. Existing approved preferences unchanged by unrelated update.
2. Raw idea: input "white dogs" starts exploration, not writing; confirmed intended message differs from literal topic. Brief records provenance, unresolved fields and approval; incomplete idea can be saved and resumed.
3. Detailed input: given ten Friday posts for named rubric, don't re-ask count/cadence/rubric. Summarize and approve; generate main plus derived spines with distinct angles.
4. Context: explicit idea B beats active idea A; ambiguous open ideas prompt; completed post searchable by ID/title; new idea never overwrites existing.
5. Generic draft without spine: sufficient context produces draft with true dependencies; missing context triggers focused question. Spine specialization uses same writing capability. Generate LinkedIn post and complete blog article with metadata, distinct native shapes.
6. Versions: generate v1 and v2, combine selected elements to v3; both parents retained. Change spine, only dependent descendants become stale; unrelated variant unaffected. Published version remains intact.
7. Review: detect unsupported claim, tone mismatch and stale dependency; default no mutation. Requested correction creates version and preserves meaning. Humanizer improves authentic voice without fabricated anecdotes.
8. Media: decline -> no media required; supplied avatar and reference -> composition spec, asset pointers; no generator -> honest incomplete/deferred state, import user file later; no paid call without approval.
9. Export: single and sequence packages contain approved exact versions, posting plan, actual media when required, valid paths; no drafts/secrets. Missing required media or unresolved stale dependency flagged; user can revise requirements.
10. Publish: manual confirmation records receipt; optional fake provider sent/scheduled/unknown is not published. Unknown timeout never blindly retries. No provider installed still completes manual workflow.
11. Analytics: screenshot/CSV/manual fixtures with missing/ambiguous values, capture date and platform; no fabricated numbers; same post repeated capture not independent evidence. Compare same age/definitions, report insufficient samples and no causal assertion.
12. Memory: disabled -> no learning promotion; enabled -> five distinct qualifying support posts promote; repeated snapshots don't count; ten qualifying contrary posts declassify; scope isolation, preserved evidence and log. Thresholds configurable; profile unchanged.
13. Status: deterministic counts, pending review, due/overdue, stale and analytics due from fixtures. Corrupt/delete index -> rebuild without losing metadata. Startup check configurable.
14. Recovery: interrupted writes, invalid YAML/JSON, duplicate ID, traversal and manual edits handled without silent loss; existing unrelated workspace files preserved.
15. Installation: skill metadata/link validators pass, required shared runtime/reference resources resolve in real consuming workspace, no external service required, existing repository skills unaffected.

## Personal-value trial

Use at least three real tasks as proposed starting sample: vague intuition, tool discovery with factual sources, and multiweek rubric sequence. Compare to ordinary agent prompting on equivalent input. Record active author minutes, turns, corrections, rewrite effort, final approval, ability to resume, forgotten tasks and perceived voice/native fit. User judges quality blind where feasible. Proposed success: materially less active work, majority of outputs usable with minor edits, no loss of intent, no duplicate publication claims, reliable recovery. Establish numerical thresholds with user before trial if needed; don't claim market validation from personal use.

GO decision permits implementation, not release or proof of effectiveness. If workflow management outweighs writing savings, simplify before adding integrations.
