# Setup CLI 0.4.1+ (compatible 0.4.x)

Run in the target workspace (or pass `--workspace PATH`). Use JSON stdin via a safely quoted heredoc or equivalent. JSON output reports structural state, not semantic truth. Read `content-flow --help` for the installed command surface.

- `content-flow setup read`: candidate and active metadata, technical choices, required/optional states, missing and unconfirmed IDs. `--details` includes changed candidate bodies. `active_technical` always describes the approved selection; `technical` is the candidate when present.
- `content-flow knowledge read ID [ID ...]`: approved bodies, only the requested documents. `knowledge list --type platform` discovers IDs; `knowledge search --query TEXT` returns metadata. Historical read: `knowledge read ID --version-number 1`.
- `content-flow setup save`: JSON patch; may include any of `documents`, `technical`, `fields`, `confirm`, `withdraw`, `archive`.

Example patch (illustrative, never copy values into a real profile):

```json
{
  "documents": [
    {
      "domain": "profile",
      "type": "voice",
      "title": "Voice",
      "summary": "Direct, explanatory writing",
      "status": "active",
      "tags": ["writing"],
      "body": "# Voice\nExplain the reasoning with concrete examples.",
      "provenance": "inferred"
    },
    {
      "domain": "strategy",
      "type": "platform",
      "title": "Personal blog",
      "summary": "Long-form explanations",
      "status": "active",
      "tags": [],
      "body": "Write in Italian unless the author requests otherwise.",
      "provenance": "confirmed"
    }
  ],
  "technical": {"memory_enabled": true, "startup_status": false},
  "fields": {"visual": "deferred"}
}
```

Document types: profile = identity, audience, voice, scope, visual-identity, example, inspiration; strategy = objectives, cadence, rubric, platform. Singleton IDs equal type for identity/objectives/audience/voice/scope/cadence. Other IDs are generated by CLI; omit `id` for creation, reuse the returned `id` for updates. One file per rubric and platform/account; keep authentic `example` documents separate from external `inspiration` documents. An `inspiration` is in the `profile` domain; the setup field is `inspirations`. Use separate stable IDs for independently useful references, or group closely related material. Include admired techniques, source/context and limits in the body; confirmed inspiration does not change `voice` automatically. `status` active/experimental/archived is lifecycle, not approval. `summary` is a short discovery description (max 300 characters); body is Markdown. Tags are strings. Optional `assets` is an array of imported relative file paths.

Mark a document `confirmed` only if all material content is explicitly supplied or accepted. Otherwise `inferred` or `proposed`. The CLI blocks approval until every staged document is confirmed; it also invalidates confirmation if a draft body changes manually. Confirm specific IDs only after user confirmation (`{"confirm":["voice"]}`); do not confirm unseen or changed content. `{"withdraw":["ID"]}` drops a candidate change without deleting history. `{"archive":["ID"]}` stages an archive proposal; approval still requires confirmation and required coverage. `setup discard` abandons the candidate selection, retaining files for recovery.

Technical keys: booleans `memory_enabled`, `startup_status`; strings `language`, `timezone`, `tools` (availability/intended use, no credentials); positive integers or null/default `memory_support_threshold`, `memory_contrary_threshold`. Only persist explicitly chosen technical values. Publishing remains manual. `fields` accepts optional field names with `deferred` or `declined` only; omit unknown/unanswered. Required coverage and blocked/inapplicable states are computed by CLI. Threshold defaults 5/10 apply on approval when memory is enabled. Missing optional fields do not block approval, but cover them individually unless the user chooses to finish/defer. Do not reset previously declined choices without a request.

Assets: `content-flow asset folder` creates `.content/assets/inbox`; give the path to the user if they want to add files manually. `asset list` lists local files with `imported` flag. With permission, `asset import PATH` copies a regular file into a unique managed folder. Import inbox files before referencing them; put returned relative paths in the visual-identity document's `assets`. Do not embed binaries, record credentials or claim visual inspection from file presence.

Final review: read `setup read --details`, compare changed bodies with user answers; after explicit approval, save `confirm` IDs and run `setup approve`. `missing` and `unconfirmed` must be empty. `knowledge save`, `knowledge archive`, and `knowledge approve` use the same candidate and gates; do not bypass review. Never edit `settings.json`, manifests, approved revisions or index directly.
